# بركات السحابي: قاعدة بيانات وتسجيل دخول حقيقيان (جاهز، غير مفعّل)

هذا المجلد يجعل موقع بركات يعمل على قاعدة بيانات مشتركة بين الأجهزة بدل التخزين في المتصفح. الكود مكتمل ومختبَر، لكنه **غير مفعّل**: ما دام `CLOUD_CFG.url` فارغاً في `barakat/index.html` يعمل الموقع بالوضع المحلي كما كان تماماً، ونسخة الكمبيوتر محلية دائماً.

## كيف يعمل

| الجزء | الملف | الدور |
|---|---|---|
| المخطط | `schema.sql` | 13 جدولاً: `profiles` و`accounts` و`transactions` و`finance_requests` و`cash_requests` و`takaful_policies` و`takaful_claims` و`messages` و`notifications` و`profit_distributions` و`fund_disbursements` و`audit_log` و`system_state`، وعرض `statements` لكشف الحساب، وRLS على كل جدول، ودالة `barakat_commit` للحفظ الذرّي بفحص الإصدار. |
| الخادم | `function/index.ts` | دالة Supabase باسم `barakat-api`. تتحقق من هوية المستخدم، وتطبق صلاحيات الأدوار (زائر، عميل، مدير)، وتنفذ العملية، ثم تحفظ التغييرات في معاملة واحدة، وتعيد لكل دور ما يحق له رؤيته فقط. |
| قواعد العمل | `function/engine.js` | مولَّد آلياً بأمر `node scripts/barakat-online/build.mjs` من شيفرة الموقع نفسها، فلا تختلف قواعد المرابحة والتكافل والزكاة بين الواجهة والخادم. |
| الواجهة | `barakat/index.html` | عند التفعيل تُرسل كل عملية إلى الخادم بدل تنفيذها في المتصفح، ويحفظ تسجيل الدخول جلسة Supabase ويجددها تلقائياً. |

الأمان: العميل لا يملك أي صلاحية كتابة مباشرة على الجداول، ولا يقرأ إلا صفوفه، ولا تُنفَّذ عملية مالية إلا داخل الخادم. كلمات المرور في Supabase Auth ولا تمر على قاعدة بركات.

## الاختبار المحلي (دون أي خدمة خارجية)

```bash
# Postgres يعمل محلياً، وحزمتا pg وplaywright مثبتتان
PGHOST=/var/tmp PGPORT=55432 PGUSER=postgres PG_MODULE_DIR=$PWD/node_modules \
  bash scripts/barakat-online/local/run-tests.sh
```

ينشئ قاعدة جديدة، ويطبق المخطط، ويشغّل محاكي Supabase (`local/mock-supabase.mjs`) مع الخادم الحقيقي، ثم:
- اختبار الواجهة بكل الأدوار على الكمبيوتر والجوال (`scripts/barakat-desktop/e2e.cjs`): 81 فحصاً.
- فحوص الأمان وسلامة الدفتر وRLS (`local/security.mjs`): 30 فحصاً.
- التزامن بين نسختين من الخادم (`local/concurrency.mjs`): 16 تحويلاً متزامناً دون فقد.

ويعمل الاختبار نفسه تلقائياً في GitHub Actions (job `cloud` في `barakat-desktop.yml`).

## التفعيل (خطوة واحدة من صاحب المشروع)

**الخطوة الوحيدة المطلوبة:** توفير مشروع Supabase مستقل لبركات. منظمة Supabase الحالية على الخطة المجانية ومشغولة بمشروعين (الحد الأقصى)، فالخيار إما ترقية المنظمة، أو إيقاف أحد المشروعين، أو إنشاء منظمة جديدة لبركات.

بعدها ينفذ Claude الباقي في دقائق:
1. تطبيق `schema.sql` على المشروع الجديد.
2. نشر `function/index.ts` و`function/engine.js` دالةً باسم `barakat-api` مع `verify_jwt = false` (الدالة تتحقق من الهوية بنفسها لتخدم الزائر أيضاً).
3. وضع رابط المشروع والمفتاح العام في `CLOUD_CFG` داخل `barakat/index.html`.
4. إيقاف التسجيل العام في إعدادات Auth (الحسابات تُنشأ عبر الخادم فقط).
5. الدمج، ثم اختبار الموقع المنشور بكل الأدوار.

عند أول طلب ينشئ الخادم حسابات التجربة وبياناتها تلقائياً (المدير `admin@barakat.qa` والعملاء)، ويُنصح بتغيير كلمة مرور المدير فور التفعيل.
